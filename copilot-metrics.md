## Contribution calculation (simple + defensible)

I estimate Copilot contribution by milestone using a weighted LOC method:

For each milestone i:
- LOC_i = lines added/changed in that milestone
- CopilotShare_i = (CopilotAcceptedLines_i / LOC_i)

Overall Copilot contribution:
Copilot% = ( Σ(LOC_i * CopilotShare_i) / Σ(LOC_i) ) * 100

Acceptance rate:
AcceptanceRate% = (AcceptedSuggestions / ShownSuggestions) * 100

Time saved estimate:
TimeSavedHours = (ManualEstimateHours - ActualHours)

Where:
- ManualEstimateHours: estimated time without Copilot (~10-12 hours for this project)
- ActualHours: actual time spent with Copilot (~5-6 hours)

## How I estimate Copilot contribution
- I count a block as "Copilot-generated" if it was produced by Copilot suggestion and accepted with minimal edits (<20% changes)
- If I heavily rewrote it (logic changes, refactor), I count it as "manual"
- Test fixes and dependency additions are counted as manual work

## 3 Key learnings

1. **Copilot excels at boilerplate but needs guidance on test stability**
   - Generated ~70% of service layer, DTOs, and repository code with minimal edits
   - Test code required more manual intervention: @Transactional for isolation, correct matchers for BigDecimal/dates, and precise expected counts
   - Lesson: Always verify generated test assertions against actual data

2. **Dependency management requires manual attention**
   - Copilot suggested core dependencies but missed jackson-datatype-jsr310 for Instant serialization
   - Had to manually add and configure JavaTimeModule in tests
   - Lesson: Review and test dependency requirements, especially for date/time handling

3. **Domain logic (filters, ranges) needs human validation**
   - Copilot generated Specification API code structure well
   - Required manual fixes for inclusive/exclusive range boundaries and BigDecimal precision
   - Edge case handling (invalid inputs, boundary conditions) mostly manual
   - Lesson: Copilot accelerates coding but critical business logic review is essential
